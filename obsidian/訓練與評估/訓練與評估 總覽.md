## 執行順序

```bash
# 1. 先驗證架構（1 分鐘）—— 跳過這步是在賭
python src/overfit_test.py                     # ce → < 0.01

# 2. 煙霧測試訓練腳本（4~14 分鐘）
python src/train_stage1.py --train data/manifest/dev-clean.tsv \
    --epochs 1 --val-every 200 --out exp/smoke

# 3. 正式訓練（8.3 小時）
nohup python src/train_stage1.py > exp/stage1_tc100.log 2>&1 &

# 4. 評估
python src/evaluate.py --ckpt exp/stage1_tc100/best.pt \
    --out exp/hyp/dev-clean.nobias.tsv --mode nobias --limit 50
```

**順序的意義**：每一步的成本遞增（1 分鐘 → 14 分鐘 → 8 小時），所以把最便宜的檢查放最前面。

## 論文 Stage 1 的設定（3.4 節）

> Stage 1 (ASR Training): We jointly train the audio adapter and CTC module **from scratch** while fine-tuning the backbone LM via LoRA for **10 epochs** with a **batch size of 4**. To prevent over-reliance on biasing information, prompts are constructed by sampling **up to 5 positive entities within a 10-entity set**. Optimization is performed using a combination of CTC and cross-entropy losses, with weights set to **0.3** and **1.0**.

| 項目 | 論文給了 | 我的設定 |
|---|---|---|
| epochs | 10 | 10 |
| batch size | 4 | 4 |
| CTC / CE 權重 | 0.3 / 1.0 | 0.3 / 1.0 |
| prompt entity | 最多 5 正 / 共 10 | 同 |
| 訓練對象 | adapter + CTC（從零）+ LoRA | 同 |
| **learning rate** | ❌ 未給 | 1e-4 |
| **optimizer** | ❌ 未給 | AdamW, wd=0.01 |
| **scheduler** | ❌ 未給 | linear warmup 3% + decay |
| **grad clip** | ❌ 未給 | 1.0 |
| **seed** | ❌ 未給 | 42 |
| **訓練資料** | 960h | **先 100h**（downscale） |

## 📌 教授交辦：學習曲線對照實驗

> [!important] 這不是附帶工作，而是驗證論文核心 claim 的唯一方法
> 論文 4.1 的 claim 是**過程性**的：
> > baseline Bias-Loss 必須用 joint objective（disc + log loss）才能 **prevent training collapse**；MPD-Loss 與 DPD-Loss 可 **converge as standalone objectives**。
>
> 「collapse」和「converge」**只能從 loss 曲線看出來**，Table 1 的 Recall 數字看不出來。
>
> **而論文沒有提供這張圖**（只有 Figure 4 的靜態分數分布）→ 這會是我自己產出、論文沒有的證據。

### 要跑的四組對照（Stage 2，同資料同超參數，只換 loss）

| 實驗 | Loss | 預期 |
|---|---|---|
| A | discriminative only（**不加** aux log loss） | **崩潰** ← 論文沒跑這組，是關鍵對照 |
| B | discriminative + log loss (w=0.1) | 收斂（論文 baseline） |
| C | MPD-Loss 單獨 | 收斂 |
| D | DPD-Loss 單獨 | 收斂 |

四條曲線畫在同一張圖。**A 崩潰而 C、D 平順下降 → claim 重現。**

### 要記錄的量

```
Stage 1: train/ctc_loss, train/ce_loss, train/total_loss, val/wer, train/lr

Stage 2: train/loss, val/recall_at_20, val/recall_at_50,
         train/pos_score_mean, train/neg_score_mean   ← 對應論文 Figure 4
```

> [!tip] 最後兩個特別值得記
> 論文 Figure 4 說 Bias-Loss「無法拉高正樣本分數」、MPD「無法壓低負樣本」、DPD「兩者皆可」。
> **逐 step 記錄正負樣本分數平均值，可畫出那三種行為的動態演化過程** —— 資訊量多於論文的靜態分布圖。

### 論文 Stage 2 的設定

> Stage 2 (Scoring Training): **All previously trained parameters are frozen.** A newly initialized discriminative projector and an **additional LoRA module** within the backbone LM are trained for **7 epochs** with a **batch size of 1**. This stage utilizes a candidate list of **M = 120** entities. Notably, while the baseline discriminative loss requires an **auxiliary log loss (weight 0.1)** to converge, our proposed MPD-Loss and DPD-Loss function effectively as **standalone objectives**.

> [!warning] Stage 2 的技術難點：121 次 forward
> 論文 instruction 是「判斷**這一個** text 在不在音檔裡」（單數），加上 M=120、batch size=1
> → **每個候選各跑一次 forward，一個 utterance 共 121 次**。
>
> 而 `seg1 + audio` 這 105 個 token 對 121 次完全相同 → **必須用 KV cache（`past_key_values`）**，否則訓練時間不可接受。
>
> **論文完全沒提這件事怎麼處理。**

### 論文的推論設定

> During inference, candidate entities are ranked by discriminative scores. We adopt a **top-K strategy (K=10)** to select the target entities for the ASR prompt, which is called **biasing target identification (BTI)**. To further mitigate performance degradation from negative entities, we use the score of the special token **`<unbiased>` as a threshold** to filter low-score entities, as 99% of our utterances contain fewer than 10 entities.
