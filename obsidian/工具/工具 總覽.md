## 「用論文有給的數字反推它沒給的」

> [!important] 這是 reproduce 最有用的技巧
> 論文沒給 adapter 架構、CTC 詞彙、projector 的 D′、LoRA rank（TODO 疑點 #3~#6），
> 但給了 **777M 總參數量**。
>
> ```
> 777M − 636.8M(encoder) − 134.5M(LM) = 5.7M  ← 所有可訓練元件的總預算
> ```

### 定案 1：CTC 詞彙必須是字元級

| CTC 詞彙 | 參數量 | 佔預算 |
|---|---|---|
| BPE 49152 | 28.3M | **497%** ❌ 爆 5 倍 |
| 字元 29 | 18.4K | 0.3% ✅ |

→ 已用實際資料確認詞彙內容（見 [[dataset]]）：空格 + 撇號 + a-z = 28，加 blank = 29。

### 定案 2：LoRA rank ≈ 16

```
5.7M − adapter/CTC 2.97M − projector 0.33M ≈ 2.4M → 兩組各 1.2M
30 層 × (q_proj 18,432 + v_proj 12,288) = 921,600  (r=16)
```

→ 實測 `trainable params: 921,600`，**與推算完全一致** ✅（見 [[lora_setup]]）

### 最終驗證

```
adapter 2,949,696 + CTC 16,733 + LoRA(asr) 921,600 = 3,888,029      ← [[model]] 實測吻合
再加 projector 333K + LoRA(scoring) 921K = 5.14M / 5.7M             ← 塞得進去 ✅
```

**整個架構的規模與論文宣稱的 777M 一致。**

## 驗證方法論的三個教訓

> [!tip] 1. 用理論值檢查 loss 的量級
> | loss | 理論基準 | 公式 |
> |---|---|---|
> | CTC | 10~17 | `(T·ln(C) − ln(對齊路徑數)) / S` |
> | CE（隨機初始化） | 10.80 | `ln(vocab) = ln(49152)` |
> | CE（預訓練 LM） | **明顯低於 10.80** | 實測 5.60 |
>
> 訓練前就能判斷有沒有 bug。算出 0.001 或 500 就是錯了，不用等訓練完。
>
> 而且「預訓練模型的初始 CE 應明顯低於 ln(vocab)」可以反過來**驗證權重真的載入了**。

> [!tip] 2. 選對指標
> 逐元素相對誤差對「含大量接近零值」的張量是**壞指標**（被小值主導）。
> 該用 **MAE / std** 或 **餘弦相似度**。詳見 [[效能分析與 bf16]]。

> [!tip] 3. 成本遞增的檢查順序
> ```
> py_compile (0.1 秒) → pyflakes (1 秒) → 單檔驗證 (秒) →
> 過擬合測試 (1 分鐘) → 煙霧測試 (14 分鐘) → 正式訓練 (8 小時)
> ```
> 把最便宜的檢查放最前面。
