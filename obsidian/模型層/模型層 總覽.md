## 兩個靠「參數預算反推」定案的設計

> [!important] 論文沒給，但給了總參數量 777M
> 這等於間接給了答案。**用論文有給的數字去夾擠它沒給的數字**，是 reproduce 的常用技巧。

**1. CTC 詞彙必須是字元級（29）**

| CTC 詞彙 | 參數量 | 佔 5.7M |
|---|---|---|
| BPE 49152 | 28.3M | **497%** ❌ |
| 字元 29 | 18.4K | 0.3% ✅ |

**2. LoRA rank ≈ 16**

```
5.7M − adapter/CTC 2.97M − projector 0.33M ≈ 2.4M → 兩組各 1.2M
30 層 × (q_proj 18,432 + v_proj 12,288) = 921,600  (r=16) ✅
```

## 這一層的核心技術點

### 1. `inputs_embeds` —— audio token 怎麼進 LM

audio token 是 576 維向量，沒有 token id。所以要走 `lm(inputs_embeds=...)`，自己做 embedding 查表再 `torch.cat`。

LM 的 Transformer 層其實不知道「token」這回事，它只看到一串 576 維向量 —— 這就是 SLM 的核心把戲。詳見 [[prompt]]。

### 2. CTC 的角色是「對齊器」不是「辨識器」

> [!important] CTC 有兩條獨立輸出路徑，共用同一組 hidden state
> ```
>                   adapter 輸出 (B, L', 576)
>                         │
>             ┌───────────┴───────────┐
>             ↓                       ↓
>       nn.Linear(576, 29)      （不經任何轉換）
>             ↓                       ↓
>       CTC logits (29 維)      hidden (576 維)
>             ↓                       ↓
>       ① 算 CTC loss            ③ 用 ② 篩選位置
>       ② argmax → 找出哪些         ↓
>          是 blank / 重複      audio tokens → 餵給 LM
> ```
>
> - **CTC logits（29 維）只用來算 loss 和決定「哪些 frame 要留」**
> - **真正餵給 LM 的是 576 維 hidden state**，不是 29 維 logits
>
> 為什麼不能把 logits 餵給 LM？29 維只含「這 frame 是哪個字母」，而 576 維含豐富的聲學語意（語者、語調、發音細節）。壓到 29 再給 LM，等於先把音訊轉成文字再處理 —— 那就退化成 baseline 的 CTC-Filter 做法，會有論文批評的 **error propagation**。
>
> 論文那句 *"generates frame-level **alignments**"* 用的是 alignment（對齊）而非 transcription，就是這個意思。

### 3. 為什麼 adapter 必須降採樣

SmolLM2 context window 只有 **2048**：

```
1500 audio + ~30 instruction + ~5 entity + ~40 transcription ≈ 1575
```

單次勉強可行，但 **Stage 2 一個 utterance 要跑 121 次 forward** → 計算上不可行。
**這正是論文 Table 2「N=5000 → OOM」的機制。**

## 這一層的通則教訓

| 坑 | 通則 |
|---|---|
| `torch.tensor([True])` 建在 CPU → 上 GPU 後 `torch.cat` 報錯 | **函式內新建 tensor 一律指定 `device=某個輸入.device`**。CPU 測試時完全看不出來 |
| transformers 5.x 沿用 checkpoint dtype → Whisper fp32、SmolLM2 bf16 不相容 | **所有 `from_pretrained` 明確指定 dtype** |
| 先包 peft 再凍結 → 可訓練參數變 0、loss 不降、不報錯 | **凍結 → 包 peft**，順序不能反 |
| adapter 誤放進 `no_grad` → 永遠學不到但 loss 仍會降 | 可訓練模組**絕不能**在 `no_grad` / `autocast` 區塊內 |
| `len(字串)` 當成 token 數 | 長度一律用 `.shape[0]` |
| CTC loss 忘記 `log_softmax` | 不會報錯，只會算出錯的數字。**log 機率永遠是負的**，可用來檢查 |
